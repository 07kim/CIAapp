# デザイン原則・禁止事項台帳

最終更新: 2026-11-05

この文書は、これまでのレビューで採用されたデザイン原則と、「やめる」「使わない」「復活させない」と決まった事項を検索しやすくまとめた実務用索引です。

画面の正式な挙動は`PRODUCT_SPEC.md`、遷移とリセットは`SCREEN_FLOW.md`、技術境界は`ARCHITECTURE.md`、採否の理由は`DECISIONS.md`が所有します。この台帳だけで仕様を変更してはいけません。矛盾を見つけた場合は実装せず、資料を修正して合意を取ります。

## 1. 判断の優先順位

判断に迷った場合は、次の順に優先します。

1. 参加者が迷わず正しく操作できること
2. 謎解きの世界観と証拠を壊さないこと
3. 現実の業務システムとして自然であること
4. 読みやすさ、アクセシビリティ、誤操作防止
5. レスポンシブ、オフライン、軽量性、保守性
6. 映画的な演出や装飾

「格好よさ」を理由に、操作、可読性、証拠、性能を犠牲にしません。一般原則と個別仕様が衝突する場合は個別仕様を優先し、理由を記録します。

## 2. 基本的なデザイン4原則

### 2.1 近接 — Proximity

- 関係する情報を近くに置き、関係しない情報との間に十分な余白を設けます。
- 見出しは対応する内容へ近づけ、次の区画から離します。
- 認証記号、`ACCESS`文、説明、進行表示は視線が大きく飛ばない範囲にまとめます。
- 操作対象と、その操作が変える内容を近くに置きます。
- 余白は空きではなく、グループ、優先順位、余韻を示す要素として使います。

### 2.2 整列 — Alignment

- 文字、アイコン、ボタン、罫線に共通の基準線を持たせます。
- 意図のない数ピクセルのずれや、左右で異なる枠幅を残しません。
- 一覧の時刻、名前、状態、金額など比較する情報は同じ列へ揃えます。
- 斜め構図や非対称構図でも、内部の文字と操作には明確な整列軸を持たせます。

### 2.3 反復 — Repetition

- 色、線幅、角の処理、アイコン、文字階層、動きの速度を、同じ意味に対して一貫して使います。
- 成功は緑、失敗・警告・ロックは赤、照合中は中立色という意味を崩しません。
- 同じ種類の操作には同じ反応を返します。
- 反復は一貫性のために使い、すべての画面を同じカード、同じ左右ワイプ、同じアニメーションにする理由にはしません。

### 2.4 対比 — Contrast

- 大小、太細、明暗、色、余白の差で、主役と補助情報を明確にします。
- 重要度が異なるものを同じ強さで並べません。
- 重要な操作は1画面に絞り、補助操作と明確な差を付けます。
- 文字をただ巨大・極太にすることを対比と呼びません。周囲の余白、行長、位置との組み合わせでジャンプ率を作ります。

## 3. 4原則に加えて守る一般原則

### 3.1 情報設計と視覚階層

- 1画面の主目的を一つに定め、最初に見る場所、次に見る場所、最後に見る補助情報を設計します。
- 見出し、本文、ラベル、注釈の段階を必要最小限にし、同じ階層へ複数のサイズを乱立させません。
- 実データを装飾より強く見せます。巨大な飾り文字が時刻、人物、金額、操作を奪わないようにします。
- 「すること」の見出しと「選択肢」を上下に分け、見出しとボタンを同じカードの連続にしません。
- 情報量を増やす場合も、参加者が操作対象や新しい謎と誤認する要素は増やしません。

### 3.2 余白、グリッド、画面密度

- 余白を削って部品を敷き詰めません。密度が必要な監視画面でも、主操作の周囲には呼吸できる領域を残します。
- 外側余白、区画間余白、部品内余白の段階を決め、場当たり的な値を増やしません。
- 大枠の中に枠、その中にカードという多重囲いを避けます。
- 四角は押せる選択肢、入力、一覧など役割がある場合に使い、説明文や空白まで習慣的に囲いません。
- 画面比率が変わっても、縦横比、中心、線幅、角丸、アイコンの形が不自然に伸縮しないようにします。

### 3.3 タイポグラフィ

- 日本語本文は読みやすい書体・太さ・行間を使い、極太書体を全要素へ適用しません。
- 英語の等幅・システム文字は短い状態ラベルへ限定し、日本語本文の代わりにしません。
- 小さな補助英字を主要情報に使いません。
- 長文をすべて大文字、過度な字間、中央揃えにしません。
- 改行位置を制御し、単語、数字、単位、名前が不自然に分断されないようにします。
- フォント読み込みに失敗しても情報階層が崩れない代替書体を指定します。

### 3.4 色とコントラスト

- 色だけで状態を伝えず、ラベル、形、アイコン、位置も併用します。
- 通常サイズの文字は背景とのコントラスト比4.5:1以上、大きな文字は3:1以上を目標にします。
- 入力枠、アイコン、フォーカスなど重要な非文字要素は周囲に対して3:1以上を目標にします。
- 赤や緑を広い面へ常時使わず、状態変化や重要な瞬間へ限定します。
- 透明度を下げすぎて読めない文字を「雰囲気」として主要情報に使いません。
- グラデーションを装飾の初期値にしません。使用する場合は矩形の端、クリップ境界、色の段差を実画面で確認します。

### 3.5 操作の見つけやすさと反応

- 押せるものは押せるように見せ、押せないものをボタンのように見せません。
- すべてのカスタムボタンにホバー、フォーカス、押下、無効、処理中の状態を必要に応じて用意します。
- 押下後は即座に視覚反応を返し、重複送信を防ぎます。
- 主操作を1〜2個に絞り、同じ強さの主要ボタンを大量に並べません。
- iPadの主要タッチ領域は44×44pt以上を基本とし、隣接操作との間隔も確保します。Webの最低基準として24×24 CSS px未満の密集した操作を作りません。
- 見た目のアイコンが小さくても、透明な操作領域を十分に持たせます。
- ダブルクリック、Z字タッチなど特殊操作は、誤発火、タッチとポインターの二重発火、文字選択を防ぎます。

### 3.6 キーボードとフォーカス

- 主要操作はキーボードでも到達・実行できるようにします。
- フォーカス順を見た目と操作順に合わせます。
- フォーカス表示を消しません。暗背景や明背景のどちらでも見える形にします。
- モーダル表示中は背景へフォーカスを逃がさず、閉じたら元の起点へ戻します。
- Esc、Enter、Spaceの役割は画面内で矛盾させません。

### 3.7 モーダル、確認、エラー

- モーダルは背景の文脈を残す必要がある操作に使い、何でも全画面へ切り替えません。
- 破棄、呼び出し、ホーム復帰など影響のある操作は、必要な場合だけ確認を挟みます。
- エラーは何が起きたか、次に何をすればよいかを短く示します。
- エラーで入力内容を消す場合は仕様に明記し、利用者がやり直せる状態へ戻します。
- 結果表示と背景の見出し、診断部品、進行線を重ねません。
- 成功・失敗を判定前の色や形で漏らしません。

### 3.8 モーションと時間設計

- 動きには開始、加速、減速、保持、余韻、次画面への受け渡しを設計します。
- 読める前に消える、途中で見切れる、結果が出た直後に別画面へ飛ぶ演出を作りません。
- 画面ごとに役割の異なる転換を使い、同じ左右スライドだけを反復しません。
- 大きな移動、回転、拡大、点滅を同時に常時動かしません。
- 1秒間に3回を超える強い閃光を使いません。
- `prefers-reduced-motion: reduce`では、非必須の移動、ズーム、回転、粒子を停止または単純なフェードへ置き換えます。
- 動きを減らしても、情報、状態、操作結果は失わせません。

### 3.9 レスポンシブとキオスク

- 特定のスクリーンショット幅だけで整えず、対象端末、低い画面、狭幅、縦向きを確認します。
- 横スクロールを発生させません。
- 文字やアイコンの重なり、切れ、極端な縮小を許容しません。
- 固定UIが本文やフォーカスを覆わないようにします。
- CIAappはPCを主対象として狭幅でも必要情報を保持し、cia-selfはiPad横向きでページ全体を固定します。

### 3.10 性能、オフライン、安定性

- 装飾のために毎フレームDOMを大量更新しません。`transform`と`opacity`を優先します。
- Canvas/WebGLはフレームレート、DPR、リサイズ、非表示タブ停止を制御します。
- 常時演出を追加するときは、低性能端末で操作遅延やタップ抜けがないか確認します。
- 外部CDN、外部フォント、外部音源へ依存せず、通信断でも主要操作を維持します。
- 画像は縦横比を崩さず、必要な解像度と適切な容量で配信します。
- サービスワーカー更新後に古いUIが残り続けないようにします。

### 3.11 文言、現実感、世界観

- 操作者が実際に見る業務用語を使い、作り手向けの説明を画面へ出しません。
- 「謎」「答え」「デモ」「仮」「次のフェーズ」などイベント外の言葉を使いません。
- 実在製品やOSのロゴ、標準壁紙、画面をそのまま複製しません。操作慣習だけを参考にして独自表現へ置き換えます。
- 参考サイトの色、ブランド、文章、素材、レイアウトをコピーせず、原理を分析してCIA Internet Co.用に再構成します。
- 架空ログ、診断、商品、履歴は現実に存在しそうな値を使いますが、証拠と誤認する内容は入れません。

### 3.12 アイコン、画像、音

- アイコンは同じ線幅、角、塗り、比率、視覚サイズで統一します。
- 錠前、再生、カード、袋、支払いなどは一目で意味が分かる標準的な形にします。
- Unicode記号、文字、即席CSS図形を正式な機能アイコンの代用にしません。
- 装飾画像が文字や操作へ重ならない安全領域を確保します。
- 音だけで成功・失敗を伝えません。ミュートや音声利用不可でも操作できます。
- BGMや常時環境音を流さず、短い操作音を意味のあるイベントだけに使います。

### 3.13 Apple HIG準拠 — 特にcia-self

Appleの正式名称はHIG（Human Interface Guidelines）です。iPad横向きで使用する`cia-self`は、Webアプリで実現可能な範囲でApple HIGを必須の設計基準として扱います。CIAappはPC向けのためApple風の外観にはしませんが、可読性、明確な反応、多様な入力、動きを減らす設定などの共通原則は適用します。

#### 適用方針

- HIGをApple風の半透明素材、角丸、標準アプリの模倣と解釈しません。CIA MARTの独自ブランドと実店舗セルフレジの外観を維持し、HIGから操作性とアクセシビリティの原則を採用します。
- HIGは更新されるため、大きなUI変更の前にApple公式の最新版を確認します。
- HIGと確定済みのイベント仕様が衝突する場合は、参加者の必須導線を守り、例外の理由、代替手段、影響を`DECISIONS.md`へ記録します。

#### 親しみやすさと一貫性

- タップは選択・実行、ドラッグは移動、スワイプはスクロールなど、一般的なジェスチャーの意味を勝手に変えません。
- 同じ見た目のコントロールは同じ動作をし、同じ操作へ異なる見た目を乱立させません。
- 押せる状態、押下中、処理中、無効、完了、失敗を明確に示します。
- 利用者の現在地、選択内容、進行状況を保ち、画面変更で文脈を失わせません。
- 通常利用者が頻繁に行う操作へ長い装飾アニメーションを毎回挟みません。

#### タッチ、ポインター、キーボード

- iPadの主要コントロールは44×44pt以上の操作領域を確保します。見た目が小さいアイコンにも十分な透明操作領域を持たせます。
- 隣接操作の間に誤タップを防ぐ余白を設け、反応領域を重ねません。
- タップ後は遅延なく押下反応を返し、処理中であることを示します。
- ホバーでしか分からない情報や操作を作りません。タッチだけで通常会計を完了直前まで操作できるようにします。
- タッチ以外にキーボード、ポインター、支援技術からも主要操作へ到達できるようにします。
- Z字タッチは従業員用の意図的な隠し入口であり、参加者の必須操作には使用しません。一般操作へ独自ジェスチャーを追加せず、Z字の存在を通常利用画面で示唆しません。

#### レイアウト、Safe Area、文字サイズ

- `env(safe-area-inset-top/right/bottom/left)`を考慮し、画面端、ホームインジケータ、ブラウザUIに重要な文字や操作を密着させません。
- iPad横向きだけに固定値で合わせず、利用可能な表示領域、縦向き、Split View相当の狭幅、表示拡大、文字サイズ変化へ適応します。
- 画面サイズが変わっても機能を削除せず、並び替え、縦積み、内部スクロールで同じ操作を保ちます。
- 文字拡大時に固定高さで切らず、行の高さ、複数行、縦積みを許容します。
- 背景画像やアイコンの縦横比を変更せず、必要ならクロップまたは余白で対応します。
- 日本語と英語で文字長が変わっても、ボタン、金額、進行表示を重ねません。

#### 主操作、ボタン、フィードバック

- 1画面の強い主操作は原則1つ、多くても2つに絞ります。すべてのボタンを同じ強さにしません。
- ボタン名は結果が予測できる短い動詞または名詞にし、曖昧な`OK`だけで重要操作を実行しません。
- アイコンだけで意味が伝わりにくい操作には、視覚ラベルとアクセシブルネームを付けます。
- 成功、失敗、読取中、未登録、係員呼出などの状態は、色だけでなく文言、形、必要に応じて音を組み合わせます。
- アラートやモーダルは利用者の作業を中断するため、影響に見合う場面だけに使います。軽い案内を毎回アラートにしません。
- 破棄や中止は結果を明示し、誤操作の影響が大きい場合だけ確認を挟みます。

#### カメラ権限とプライバシー

- カメラ権限はアプリ起動直後ではなく、商品読取を始めてカメラが必要になった時点で要求します。
- 権限要求の直前または同じ文脈で、商品バーコード読取に使うことを短く説明します。
- 独自画面でOSの権限ダイアログを偽装しません。許可を誘導する報酬、脅し、紛らわしい`許可`ボタンを置きません。
- 拒否・利用不可・カメラ取得失敗を区別し、設定確認または係員呼出など次の行動を案内します。
- 映像を保存・送信しない現在の設計を維持し、将来変更する場合は先に仕様と説明を更新します。

#### モーションとアクセシビリティ

- モーションは状態、因果関係、画面のつながりを説明する目的で使い、装飾だけの過剰な移動を追加しません。
- 頻繁なタップへ長いモーションを付けず、短く正確な反応を返します。
- 移動方向と画面の因果を合わせます。上から出たものを理由なく横へ退場させません。
- `prefers-reduced-motion`では大きな移動、ズーム、回転を抑え、フェードや即時切替へ置き換えます。
- 音、色、動きのどれか一つだけを唯一の情報伝達手段にしません。

#### 実機確認

- 使用予定のiPadで、横向き、縦向き、表示拡大、文字サイズ、カメラ許可・拒否、ミュート、キーボード、タッチを確認します。
- ブラウザのアドレスバーやホーム画面追加後の表示差、Safe Area、100dvh、ソフトウェアキーボード表示時の切れを確認します。
- 44×44ptの領域はCSS上の寸法だけでなく、実機で隣のボタンを誤って押さないか確認します。

## 4. 全プロジェクト共通の再導入禁止事項

次の表現や実装は、明示的な再承認がない限り復活させません。

- 意味のない`01`、`02`、ゼロ埋め番号、章番号を装飾として置く。
- 押せそうなのに反応しないボタン、時計、アイコン、タブ、メニューを置く。
- 同じ角丸カードを画面全体へ均等に並べる。
- 内容のない大きな空白、または余白をなくした過密配置にする。
- すべての見出し、説明、進行表示を四角い枠で囲う。
- 片側だけ赤い線、片側だけ太い枠、意図のない傾きを付ける。
- グラデーションを四角や`clip-path`で切り、不自然な端を露出させる。
- 巨大な文字を置くだけで画面を完成扱いにする。
- 極太フォント、同じ文字サイズ、同じボタン寸法だけで全画面を構成する。
- 文字、アイコン、装飾、進行線を重ねる。
- 成功・失敗が確定する前から緑・赤を見せる。
- 同じ左右ワイプ、同じ中央分割、同じカード出現を全画面で繰り返す。
- アニメーションを途中で切る、余韻なく消す、一度消して同じ窓を出し直す。
- カーソルへ小さな照準、光点、大円を常時追従させる。
- 常時動く装飾のために操作を重くする。
- 参考サイトのブランドや素材をそのまま流用する。
- 一般利用者に実装上の都合、内部フェーズ、仮データであることを説明する。
- UIで解決できる固定データのためにデータベースを追加する。

## 5. CIAappで復活させないもの

### 5.1 デスクトップ

- 「セキュアデスクトップ」「業務アプリケーション」などの大見出しやポータルカード。
- PC全体を「メンテナンス」でロックする構成。認証は監視カメラを選んだ後です。
- セッション終了ボタン。
- ホーム画面の放置リセット。
- デスクトップアイコンの単クリック起動、単クリック選択枠、ホバー時の外周四角枠。
- ダブルクリックできそうなのに単クリックで即起動する不自然な挙動。
- 反応しないスタート、検索、タスクバーアイコン、通知領域、時計。
- Windowsの商標画像や標準壁紙の複製。

### 5.2 認証

- 「回答を入力」「謎の答え」など、謎解きであることを露出する文言。
- 入力文字を伏せ字にすること。伏せ字は未入力時のプレースホルダーだけです。
- 試行回数制限。
- 送信直後から緑または赤にして正否を漏らすこと。
- 大きな×印、銃の照準のような失敗記号。
- `ACCESS GRANTED / DENIED`を認証リングや説明から遠く離すこと。
- 認証結果を全画面へ展開すること。
- 結果の裏へ元画面の巨大見出しや診断表示を透かして重ねること。
- 判定の途中で結果窓を消し、入力窓や次画面をもう一度出すこと。
- 個別認証へキャンセルボタンを置くこと。
- 送信後に暗幕クリックやEscで判定を中断できるようにすること。
- 正解後、小型ウィンドウの中央から左右へ面を割る封印シャッター。
- 拡大円形グラデーション、円錐グラデーション、四角く切れたアパーチャ。

### 5.3 監視記録とアイコン

- カメラ状態を銃のターゲット・照準アイコンで表すこと。
- 錠前に見えない四角線だけの記号。錠前は弦、本体、鍵穴を持たせます。
- 閲覧可能な映像へ錠前を表示すること。閲覧可能は再生マークです。
- 選択状態の片側だけに色を付ける枠。
- 5件以外の映像行、追加ロック、閲覧不能ファイルを並べること。
- 「調査対象」「事件用フィルター」「運営が用意した証拠」など、正規に調査している表現。
- 参加者を惑わせるカモフラージュ映像や、いつか見られそうなダミー映像。
- 映像5の時刻を23:55以外に戻すこと。
- システムファイルへ事件の必須証拠を混ぜること。

### 5.4 ネットワーク図

- ノードをドラッグして動かす操作。
- ドラッグ時や連打時に文字選択が発生する実装。
- 接続を1本だけに制限すること。
- ノード操作をロック解除や謎進行へ結び付けること。
- 重い物理演算や新しいWebGLをノードごとに追加すること。
- 接続できそうに見える主要ノードを無反応にすること。

### 5.5 動画

- 動画音声、BGM、常時環境音、音量操作。
- ファイル選択直後の自動再生。実機評価で再承認されるまでは行いません。
- 再生位置を1秒ごとにカクカク更新すること。
- 文字表示へ小数秒を出すこと。バーは連続、文字は整数秒です。
- 動画終了時の自動ループ。
- 別映像へ切り替えても前の再生位置を保持すること。
- 全画面表示で再生、一時停止、シーク、終了操作を失わせること。

### 5.6 入退室ログとリセット

- 一ノ瀬の正式4件の間へ別人物、警備員、四ツ谷などのカモフラージュ記録を挿入すること。
- 参加者向け検索、編集、追加、削除、絞り込み。
- 巨大見出し、巨大番号、巨大日付、横長カードが記録より目立つ構図。
- 記録画面へ強い常時演出を重ね、表を読みにくくすること。
- 放置復帰を30秒へ戻すこと。現在は10秒警告、20秒復帰です。
- 動画再生中や認証判定中も放置時間を進めること。
- ホーム復帰確認へ「解除済み映像が再ロックされる」と説明すること。

## 6. cia-selfで復活させないもの

### 6.1 初期画面と全体構造

- 監視システムと同じ赤黒、高密度、サイバー、ハッキング映画風の見た目。
- 「セルフレジ」「いらっしゃいませ」を巨大見出しにすること。
- 「お買い物を始める」「デモ取引を開始」「START」を日本語の主操作にすること。
- 商品コード入力をトップへ置くこと。
- 画面上端を占有する固定ヘッダー。
- 画面全体を大きな白い説明カードで囲うこと。
- 選択肢をさらに大きな外枠でまとめること。
- 進行表示を角丸カードにすること。
- ページ全体のスクロール、バウンド、横スクロール。
- iPad横だけ整えて、縦向きや狭幅で重なり・切れを放置すること。

### 6.2 通常会計

- 「ポイントを貯める」「ポイントを使う」を最初の選択肢にすること。
- ポイントカードを選んだ後、読取成功を自動演出すること。
- 商品タイルや商品一覧から参加者が商品を選ぶこと。
- 商品コードを手入力させること。
- 未登録コードを任意の商品へ変換すること。
- レジ袋を選んでも商品明細と金額へ追加しないこと。
- 支払いなしで購入完了にすること。
- タイマーで決済成功にすること。
- 支払い完了ボタンや会計完了画面を置くこと。
- 無操作時間で勝手にトップへ戻ること。

### 6.3 係員、文言、音

- 係員ボタンを押した瞬間に確認なしで呼び出すこと。
- 「呼び出しました。来られないことがあります」のような、店舗として雑・不安を与える文言。
- 常時鳴るBGMや環境音。
- 音が出ないと操作結果が分からない設計。
- 「デモ」「スキャナーがないので進めません」など内部事情を画面へ出すこと。

### 6.4 アイコンとタッチ

- カード、ポイント、袋、支払いを文字記号や即席CSS図形で表すこと。
- Google Symbols等をネットワークから実行時取得すること。必要なSVGはローカルへ同梱します。
- 線幅、角、比率がばらばらなアイコンを混在させること。
- アイコンや装飾を見出し・説明へ重ねること。
- iOSの灰色タップハイライトを残すこと。
- 端末比率によって四隅の反応円が楕円や異なる比率になること。
- Z字を`左上 → 右上 → 右下 → 左下`のコ字順にすること。正しくは`左上 → 右上 → 左下 → 右下`です。
- Z字の制限時間を全体1.5秒にすること。各タッチ間が1.5秒です。
- `touchstart`と`pointerdown`を同じタッチで2回数えること。
- Z字成功時に目立つ音を鳴らし、隠し操作を周囲へ知らせること。

### 6.5 従業員モードと購入履歴

- 隠し画面を「裏モード」のまま一般UIへ表示すること。名称は従業員モードです。
- 従業員モードを購入履歴だけに限定すること。商品台帳、端末状態、取引設定などの運営メニューも持たせます。
- 証拠履歴だけを1件表示し、謎解き用に作ったデータだと分かる状態にすること。通常の商品名、価格、支払方法、明細を持つ自然なカモフラージュ取引も固定データとして保持します。
- カモフラージュ取引を無意味な乱数や空の商品で埋めること。現実の売店で成立する商品と合計を使います。
- 購入履歴全体を固定高さのまま切り、表を読めなくすること。
- 見出しや検索欄まで一覧と一緒にスクロールさせること。
- 証拠履歴から`20:15 / 一ノ瀬 なつき / 0719 / ¥580`を変更すること。
- 四ツ谷または社員ID`1031`の購入記録を追加すること。

## 7. 旧仕様を読んだときの扱い

- `CHANGELOG.md`は履歴なので、古い仕様も残ります。新しい日付の変更と現在の仕様書を優先します。
- `PLANS.md`のCompletedフェーズに途中案が残っていても、後続フェーズで廃止されていれば復活させません。
- 過去のスクリーンショットは問題報告の記録であり、見た目の正解例とは限りません。
- 参考URLは分析材料であり、コピー元ではありません。
- 「仮で見たい」と導入した案も、その後「やめたい」「不自然」と評価された場合は廃止済みです。

## 8. レビュー時の確認項目

### 見た目

- 主役が3秒以内に分かるか。
- 余白、整列、反復、対比の4原則を説明できるか。
- 文字、アイコン、線、装飾が重なっていないか。
- 枠やカードを外しても情報構造が成立するか。
- 赤、緑、青、太字、巨大文字を意味なく使っていないか。
- 片側だけの枠や、切れたグラデーションがないか。
- AI生成UIに見える均一なカード列、過剰な角丸、極太文字になっていないか。

### 操作

- 押せそうな要素はすべて反応するか。
- マウス、タッチ、キーボードで主要操作ができるか。
- フォーカスが見え、順序が自然か。
- 二重送信、二重タップ、誤発火がないか。
- 認証や支払いの成否を確定前に漏らしていないか。
- モーダルの背景操作と閉じ方が仕様どおりか。

### 画面変化

- アニメーションの始まり、保持、終わり、余韻が見えるか。
- 前画面と次画面が不自然に途切れないか。
- 結果窓が一度消えて出直して見えないか。
- 動きを減らす設定でも情報と操作が残るか。
- 低性能端末で入力遅延が起きないか。

### 表示環境

- CIAappのPC幅、低い画面、狭幅を確認したか。
- cia-selfのiPad横、iPad縦、狭幅を確認したか。
- 200%拡大、長い日本語、英語表示でも切れないか。
- オフライン、再読み込み、サービスワーカー更新後も最新版が出るか。
- 背景画像、SVG、音声がネットワークなしで利用できるか。

## 9. 参照した一般基準

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) — コントラスト、キーボード、フォーカス、動き、入力方式など
- [WCAG 2.2 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) — 最低24×24 CSS pxまたは十分な間隔
- [Apple Human Interface Guidelines: Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) — タッチ領域44×44pt、押下状態、主要操作の絞り込み
- [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) — Appleプラットフォーム全体の公式設計指針
- [Apple HIG: Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles/) — 親しみやすさ、一貫性、明確な反応、多様な入力、文脈保持
- [Apple HIG: Layout](https://developer.apple.com/design/human-interface-guidelines/layout) — Safe Area、表示領域への適応、文字サイズ、ローカライズ
- [Apple HIG: Gestures](https://developer.apple.com/design/human-interface-guidelines/gestures) — 標準ジェスチャー、即時反応、代替入力
- [Apple HIG: Motion](https://developer.apple.com/design/human-interface-guidelines/motion) — 目的のある短い動き、過剰なモーション回避
- [Apple HIG: Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy/) — カメラ等の権限を必要な時点で理由とともに要求
- [Apple UI Design Dos and Don'ts](https://developer.apple.com/design/tips/) — 画面適合、可読性、整列、余白、画像比率
- [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion) — 非必須モーションを減らす利用者設定

これらは最低基準または一般原則です。基準を満たしていても、CIA Internet Co.の個別仕様、物語、実機の使いやすさを満たさなければ採用しません。
