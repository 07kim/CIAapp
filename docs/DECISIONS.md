# 設計判断記録

- 最終更新日: 2026-10-30
- 状態表記: `Accepted` / `Proposed` / `Deferred` / `Superseded`

## D-001: React + TypeScript + Viteを採用

- 状態: Accepted
- 理由: 複数画面、ロック状態、タイマー、動画状態を型付きコンポーネントとして分離しやすい。Vercelへ静的配信しやすく、初版に不要なサーバー機能を持ち込まない。
- 影響: HTML、CSS、JavaScriptを直接1ファイルへ集約しない。Next.jsは初版では採用しない。

## D-002: PCホームを最初の画面とする

- 状態: Accepted
- 理由: 監視カメラと入退室ログを別アプリとして提示するため。
- 影響: 「メンテナンス」の謎はPC全体ではなく、監視カメラアプリの入口ロックとなる。

## D-003: ホーム復帰で監視カメラの解除状態を保持しない

- 状態: Accepted
- 理由: 次の参加者に解除状態を引き継がないため。
- 影響: 手動または放置でホームへ戻ると、入口、映像1、映像2を再ロックする。

## D-004: 全画面を放置判定対象にする

- 状態: Accepted
- 理由: 謎画面を開いたまま参加者が離れても、自動で初期状態へ戻すため。
- 例外: PCホーム、動画再生中、約2.8秒の認証判定中。

## D-005: 動画は無音・手動再生・非ループ

- 状態: Accepted
- 理由: 会場での意図しない音声や再生を避け、参加者に操作を委ねるため。
- 影響: 再生、一時停止、シークのみを提供し、音量操作を設けない。

### 補足: UI効果音

- 状態: Accepted
- 動画本体は無音のまま維持する一方、アプリ起動、認証、解錠、ファイル選択、再生操作、放置警告には短いシステム効果音を使用する。
- UI効果音は動画の音量機能ではなく、Web Audioで端末内生成する操作フィードバックとして扱う。

## D-006: 赤黒の業務用サイバーUI

- 状態: Accepted
- 理由: 提供された監視ソフトと診断ソフトの参考画像、および映画的なサイバー感の要望に合わせるため。
- 影響: CIA Internet Co.ロゴは透過し、暗色背景用に文字を明色化したバージョンを用意する。

## D-007: データベースを先に導入しない

- 状態: Accepted
- 理由: 固定された謎解きデータにはデータベースが不要であり、オフライン要件と保守性を優先するため。
- 影響: 入退室ログが固定ならJSONを使用する。運営中の更新が必要と確定した場合にSheets / GASを再評価する。

## D-008: GitHubとVercelの変更フロー

- 状態: Accepted
- 理由: 本番へ直接変更を入れず、差分と動作を確認してから公開するため。
- 影響: `main`を本番用とし、変更は作業ブランチとPull Requestを基本とする。Vercel Previewと自動検査を確認後にマージし、`main`への反映で本番を自動更新する。2026-10-27のユーザー承認に基づき、以後は承認済みフェーズの検証完了を一区切りとして、仕様書・変更履歴・コードを一緒にcommit/pushし、Vercelの反映結果まで確認する。
- 公開ルール: 初回リポジトリは謎の答えと内部仕様を含むため非公開とする。認証切れ、新しい外部サービス、公開範囲の変更は別途ユーザー確認を必要とする。

## D-009: QRコード方式

- 状態: Deferred
- 理由: 初版はPC上で直接映像を見る方式を採用するため。
- 再検討条件: リハーサルでPC前の滞留が問題になった場合。

## D-010: 監視カメラ入口のビジュアル

- 状態: Deferred
- 理由: PCロック風であること以外、最終デザインが未決定。

## D-011: 入退室ログのデータ元

- 状態: Superseded by D-027
- 選択肢: 固定JSON、Google Sheets + Google Apps Script、その他のデータサービス。
- 決定条件: データ内容、更新者、更新頻度、同時利用、オフライン時の期待動作が確定すること。

## D-012: Phase 9前の暫定入退室ログ

- 状態: Superseded by D-027
- 理由: 正式仕様を待つ間も、監視映像と照合する謎解き体験を成立させるため。
- 影響: 固定のヒントログを`StaticAccessLogRepository`から表示する。正式な項目・検索・外部データ連携はPhase 9に閉じ込め、暫定UIと混在させない。

## D-013: アプリシェルをService Workerで保持

- 状態: Accepted
- 理由: 会場の通信状態に左右されず、PCホーム、認証、固定ログ、ローカル資産を利用できるようにするため。
- 影響: 本番ビルドのHTML、JavaScript、CSS、ロゴを同一配信元からキャッシュする。`LOCAL READY`は現在のアプリシェルが保存済みであることを示す。動画の完全保持は最終ファイル容量の検証後に完了判定する。

## D-014: 認証をパスワード照合演出として表現

- 状態: Accepted
- 理由: 「回答を入力」という謎解き画面らしさを抑え、社内セキュリティ端末を操作して解除している体験を強めるため。
- 影響: システムパスワード欄は伏せ字のプレースホルダーを表示し、入力中の文字は確認できるようにする。送信後は照合リング、進行ゲージ、信号グラフ、成功チェックまたは失敗記号を表示し、不正解時は入力を消して同じ画面へ戻す。動きを減らすOS設定を尊重する。

## D-015: PCホームはデスクトップそのものとして表現

- 状態: Accepted
- 理由: 大きな見出しとカード型レイアウトは社内PCではなく業務ポータルに見えるため。
- 影響: ホームでは共通アプリヘッダーを表示せず、オリジナル壁紙、左上のショートカット、下部タスクバー、時計を備えたWindows風の全画面デスクトップを使用する。Windowsの商標画像や標準壁紙は複製しない。

## D-016: デスクトップショートカットは選択と起動を分ける

- 状態: Superseded by D-018
- 理由: 一般的なWindowsデスクトップに近い操作感とし、誤クリックによる即時起動を避けるため。
- 影響: デスクトップでは1回のクリックを選択、ダブルクリックまたはEnterキーを起動とする。スタートメニューは1回のクリックで起動する。どちらも短い起動中表示を挟んで対象画面へ遷移する。

## D-017: 高品質な社内フォレンジックOSをビジュアル基準とする

- 状態: Superseded by D-029
- 理由: 赤い細線、同心円、極小英字を多用した画面はサイバー風テンプレートに見え、求める映画的な説得力を損なうため。
- 影響: チャコール中心の階調とニュートラルな境界線を基礎に、赤は意味のある操作状態へ限定する。装飾より情報階層、余白、文字の読みやすさ、部品の統一感を優先する。

## D-018: 1回クリックではショートカットの表示状態を変えない

- 状態: Accepted
- 理由: ダブルクリック起動は維持したい一方、1回クリック後に強い選択表示が残ると今回のオリジナルデスクトップでは不自然に見えるため。
- 影響: デスクトップショートカットは1回クリックで画面遷移も選択表示も行わない。ダブルクリックまたはフォーカス中のEnterキーで起動する。スタートメニューは1回クリック起動を維持する。

## D-019: 動的ダッシュボードの表現を監視画面へ限定的に取り入れる

- 状態: Superseded by D-020
- 理由: ユーザー提示の参考動画にある、強い文字階層、巨大な識別番号、斜めの構図、滑らかなパネル切替が、求める映画的なシステム感に合うため。
- 影響: 配色とブランドはCIAの赤黒を維持し、WebGPUや常時派手に動く演出は導入しない。軽量なCSSで選択・画面切替時だけ動かし、`prefers-reduced-motion`では停止する。

## D-020: 軽量な常時モーションと映画的な画面展開を全体へ導入

- 状態: Superseded by D-021
- 理由: ユーザー提示の参考動画に近い、常に稼働しているシステム感とスタイリッシュな画面展開を、軽さと両立して求められたため。
- 影響: デスクトップから監視画面まで、走査線、信号波形、データ帯、斜めワイプを継続的に表示する。WebGPU、動画背景、JavaScriptの毎フレーム描画は使わず、CSSの`transform`と`opacity`を中心に構成する。`prefers-reduced-motion`では停止する。

## D-021: 全画面で連続する共通WebGL背景を採用

- 状態: Accepted
- 理由: ホームだけでなく監視カメラ、入退室ログ、確認表示まで参考動画と同じ動的表現へ統一し、画面遷移時の不自然な途切れをなくすため。
- 影響: 画面分岐の外側に単一のWebGL Canvasを保持し、画面ごとの描画モードは補間して切り替える。前面パネルも同じ斜めワイプ、波形、走査表現へ統一する。WebGL非対応時はCSSへフォールバックし、解像度上限、非表示タブ停止、`prefers-reduced-motion`対応を維持する。

## D-022: 前面UIと機能アイコンも動的な共通視覚言語へ統一

- 状態: Superseded by D-024
- 理由: 共通背景だけが動く状態では参考動画のような一体感に届かず、既存の四角いアプリアイコンや文字記号が画面全体の品質から浮いて見えるため。
- 影響: 主要画面の遷移へ共通の章番号、斜めブレード、小さな矩形断片を追加し、ヘッダー、パネル、一覧、端末出力、診断情報を段階表示する。アプリ、監視映像、システムファイル、端末状態、入退室要約のアイコンは細線と角張った形へ刷新する。追加演出はCSSの`transform`、`opacity`、`clip-path`を中心にし、操作判定、状態管理、WebGL背景の寿命を変更しない。

## D-023: 実動画受領まで提供静止画をプレイヤーに表示する

- 状態: Accepted
- 理由: 実動画が未完成の段階でも、5本の内容、ロック、再生操作、全画面表示を本番に近い形で確認できるようにするため。
- 影響: 「映像1」から「映像5」を同番号のアーカイブへ対応付け、ローカルキャッシュ対象とする。プレイヤーの状態管理は維持し、実動画受領後にメディア定義を差し替えられる構造とする。

## D-024: 画面の役割ごとに異なる転換を使い、装飾番号を廃止

- 状態: Accepted
- 理由: 全画面で同じ左右ワイプと意味のない章番号を繰り返すと、画面ごとの特徴が失われ、UIがテンプレート的に見えるため。
- 影響: デスクトップ、認証、監視アーカイブ、入退室ログへ、それぞれ円形、回転走査、縦シャッター、奥行きトレースの転換を割り当てる。表示ラベルは機能名・状態・実データに限定する。認証入力はスキャナーと入力チャネルを統合したコンソールへ変更し、回答判定と画面遷移は変更しない。

## D-025: 認証判定と次画面を一つの連続モーションとして扱う

- 状態: Superseded by D-026
- 理由: 判定演出の直後に無関係な固定転換が始まると操作の因果が切れ、短い演出同士も途中で見切れて感じられるため。
- 影響: 判定時間を約2.8秒へ広げ、前半は成否を伏せた中立色、後半は結果色と余韻に分ける。成功時は認証リングから広がる緑の光面と、監視画面側の`authorized`アパーチャを同じ位置・色で接続する。放置リセットは警告10秒、復帰20秒へ短縮する。

## D-026: 認証成功の接続を左右シャッターへ変更

- 状態: Superseded by D-037
- 理由: 円形グラデーションを画面全体へ拡大する方式は、補間中に色の段差、四角い描画境界、画面切替時の切り抜きが見えやすく、前後の連続性より不自然さが目立つため。
- 影響: 判定中の中立色と約2.8秒の時間設計は維持する。成功結果の最後は暗色の左右面を中央へ閉じ、監視アーカイブ側で同じ面を左右へ開く。接続面は不透明な単色と細い緑の中心線で構成し、巨大な円形グラデーションと円形clip-pathを廃止する。

## D-027: 入退室ログはローカル固定データ4件を表示

- 状態: Accepted
- 理由: 正式仕様で表示内容、順序、閲覧専用、20秒放置復帰、オフライン利用が確定し、運営中に更新する要件がないため。
- 影響: `StaticAccessLogRepository`から、2026年11月20日の一ノ瀬なつき（`ID-0719`）による社長室の20:00入室、20:15退室、20:30入室、20:45退室を順番どおり返す。別記録は挿入せず、検索・編集・Sheets・GAS・データベースは導入しない。

## D-028: 大きな切り抜きグラデーションを画面転換に使用しない

- 状態: Accepted
- 理由: グラデーション面を回転・縮小する入口転換で矩形の描画境界が目立ち、共通背景との連続性と余韻を損なったため。
- 影響: 監視カメラ入口への転換は、単色の上下シャッター、細い赤線、中央認証コアで構成する。閉じた状態を保持してから上下へ開き、グラデーションの矩形クリッピングを廃止する。

## D-029: ランディングページ級の映画的演出を全画面へ適用

- 状態: Accepted
- 理由: 抑制した業務画面より、参考サイトのように常時動き、画面ごとに異なる展開と奥行きを持つ強い体験が求められたため。
- 影響: 既存の連続WebGL背景に、ポインター追従照準、軌道、走査ビーム、テレメトリ、データ帯を重ねる。全画面へ適用しつつ操作要素を覆わず、狭幅、動きを減らす設定、WebGL非対応、オフライン動作を維持する。大きな切り抜きグラデーションは再導入しない。

## D-030: 提供されたIllustrator原稿を正式ロゴの原本とする

- 状態: Accepted
- 理由: 会社ロゴの正式なベクター原稿が提供され、従来の仮画像より正確な形状と文字組みを使用できるため。
- 影響: Illustrator原稿を`design/source/`へ保管し、Web用の透過PNGを書き出してヘッダー、デスクトップ壁紙、監視待機画面へ使用する。実行時は外部サービスへ依存しない。

## D-031: 入退室ログは概要と時系列を分離した管制画面とする

- 状態: Accepted
- 理由: 巨大な見出しと横長カードが記録内容より強く、狭幅ではコミカルな大きさに見えたため。
- 影響: タイトルを抑え、対象日・区画・記録種別・整合性をコンテキスト領域へまとめ、4件を縦の時系列として主表示する。正式な記録値、順序、閲覧専用、データ境界は変更しない。

## D-032: 定常画面では演出強度を下げる

- 状態: Accepted
- 理由: すべての演出が常に同じ強さで動くと、実在する社内システムより展示用の画面に見え、記録閲覧時の自然さを損なうため。
- 影響: 強い動きは起動、認証、画面切り替えへ集中させる。入退室ログの定常表示では共通照準、軌道、走査、テレメトリの不透明度を下げ、見出し、日付、記録行を業務画面に近い寸法と表形式へ整える。

## D-033: 映像個別認証は監視画面へ重ねるモーダルとする

- 状態: Accepted
- 理由: ロック映像の選択時に中央表示を暗号化専用画面へ置き換え、さらに暗幕を重ねる構成では、認証ウィンドウの背後が黒または空に見えて操作の連続性を損なうため。
- 影響: 映像1・2を選択しても監視画面の表示状態は維持し、半透明暗幕とパスワードウィンドウだけを最前面へ表示する。暗幕は背景操作を遮断し、認証前に暗幕またはEscキーで閉じると直前の監視画面へ戻る。回答判定と解除状態は変更しない。

## D-034: 映像個別認証の判定は同じウィンドウ内で完結させる

- 状態: Superseded by D-037
- 理由: パスワード送信後に全画面の判定表示へ切り替わると、監視画面へ重ねたウィンドウとしての連続性が途切れるため。
- 影響: 個別認証のキャンセルボタンを廃止し、認証前のみ暗幕クリックまたはEscキーで閉じる。照合中・成功・失敗は入力ウィンドウと同じ外形の内部へ表示し、入口認証の全画面演出は変更しない。

## D-035: カーソル追従を廃止して常時背景を軽量化する

- 状態: Accepted
- 理由: カーソルへ追従する小さな照準が不要で、マウス移動ごとの更新と高密度・毎フレームのWebGL描画が操作時の重さにつながるため。
- 影響: カーソル追従の光点・照準・大円と`pointermove`処理を削除する。軌道、走査、テレメトリ、データ帯、認証、画面転換は維持し、WebGL背景だけを30fps上限、DPR 1.25上限、リサイズ時のみ寸法更新へ変更する。

## D-036: 監視映像の状態と個別認証結果を意味のある構図で示す

- 状態: Accepted
- 理由: 全映像に同じ照準を使うとロックと再生可能の違いが伝わらず、片側だけの選択罫線や中央へ部品を重ねた認証結果は機械生成的で不自然に見えるため。
- 影響: 映像一覧は錠前と再生マークを状態に応じて切り替え、選択枠を四辺均等にする。映像1・2の認証結果は、同じウィンドウ内で認証記号と結果文を横に分け、全画面用の診断装飾を省略する。

## D-037: すべての認証結果を入力ウィンドウ内で完結させる

- 状態: Superseded by D-038
- 理由: 入口の「メンテナンス」認証だけ結果が全画面へ展開すると、映像個別認証と操作感が揃わず、認証前後のウィンドウ構造も途切れるため。
- 影響: 入口認証と映像個別認証は、どちらも入力ウィンドウの位置と外形を維持したまま内部で照合・成功・失敗を表示する。結果は認証記号と文を横に分け、成功後の画面転換は結果の余韻後に開始する。監視映像未選択時は、カメラ接続、録画範囲、ファイル数、暗号化数、待機波形を中央領域へ追加する。

## D-038: 入口認証の結果は入力画面へ重ねる小型ポップアップとする

- 状態: Accepted
- 理由: 入力ウィンドウ全体を結果表示へ置き換えると入力前の画面が消え、判定記号と`ACCESS`文の距離も広く見えるため。

## D-040: 認証結果ウィンドウを状態切替まで保持する

- 影響: `ACCESS DENIED`の早期消去アニメーションを廃止し、約2.8秒後の状態切替まで結果ポップアップを維持する。成功結果も従来どおり画面転換開始まで保持する。

## D-041: 監視端末を未登録セッションから侵入している表示にする

## D-042: 監視待機画面を編集的な非対称グリッドへ変更

## D-043: 映像解錠後の中央分割を外周認証へ変更
