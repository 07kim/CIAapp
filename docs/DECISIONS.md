# 設計判断記録

- 最終更新日: 2026-10-27
- 状態表記: `Accepted` / `Proposed` / `Deferred` / `Superseded`

## D-001: React + TypeScript + Viteを採用

- 状態: Accepted
- 理由: 複数画面、ロック状態、タイマー、動画状態を型付きコンポーネントとして分離しやすい。Vercelへ静的配信しやすく、初版に不要なサーバー機能を持ち込まない。
- 影響: HTML、CSS、JavaScriptを直接1ファイルへ集約しない。Next.jsは初版では採用しない。

## D-002: PCホームを最初の画面とする

- 状態: Accepted
- 理由: 監視カメラと入退室ログを別アプリとして提示するため。
- 影響: 「メンテナンス」の謎はPC全体ではなく、監視カメラアプリの入口ロックとなる。

## D-003: ホーム復帰で監視カメラの解除状態を保持しない

- 状態: Accepted
- 理由: 次の参加者に解除状態を引き継がないため。
- 影響: 手動または放置でホームへ戻ると、入口、映像1、映像2を再ロックする。

## D-004: 全画面を放置判定対象にする

- 状態: Accepted
- 理由: 謎画面を開いたまま参加者が離れても、自動で初期状態へ戻すため。
- 例外: PCホーム、動画再生中、約2秒の認証判定中。

## D-005: 動画は無音・手動再生・非ループ

- 状態: Accepted
- 理由: 会場での意図しない音声や再生を避け、参加者に操作を委ねるため。
- 影響: 再生、一時停止、シークのみを提供し、音量操作を設けない。

## D-006: 赤黒の業務用サイバーUI

- 状態: Accepted
- 理由: 提供された監視ソフトと診断ソフトの参考画像、および映画的なサイバー感の要望に合わせるため。
- 影響: CIA Internet Co.ロゴは透過し、暗色背景用に文字を明色化したバージョンを用意する。

## D-007: データベースを先に導入しない

- 状態: Accepted
- 理由: 固定された謎解きデータにはデータベースが不要であり、オフライン要件と保守性を優先するため。
- 影響: 入退室ログが固定ならJSONを使用する。運営中の更新が必要と確定した場合にSheets / GASを再評価する。

## D-008: GitHubとVercelの変更フロー

- 状態: Accepted
- 理由: 本番へ直接変更を入れず、差分と動作を確認してから公開するため。
- 影響: `main`を本番用とし、変更は作業ブランチとPull Requestを基本とする。Vercel Previewと自動検査を確認後にマージし、`main`への反映で本番を自動更新する。2026-10-27のユーザー承認に基づき、以後は承認済みフェーズの検証完了を一区切りとして、仕様書・変更履歴・コードを一緒にcommit/pushし、Vercelの反映結果まで確認する。
- 公開ルール: 初回リポジトリは謎の答えと内部仕様を含むため非公開とする。認証切れ、新しい外部サービス、公開範囲の変更は別途ユーザー確認を必要とする。

## D-009: QRコード方式

- 状態: Deferred
- 理由: 初版はPC上で直接映像を見る方式を採用するため。
- 再検討条件: リハーサルでPC前の滞留が問題になった場合。

## D-010: 監視カメラ入口のビジュアル

- 状態: Deferred
- 理由: PCロック風であること以外、最終デザインが未決定。

## D-011: 入退室ログのデータ元

- 状態: Deferred
- 選択肢: 固定JSON、Google Sheets + Google Apps Script、その他のデータサービス。
- 決定条件: データ内容、更新者、更新頻度、同時利用、オフライン時の期待動作が確定すること。
