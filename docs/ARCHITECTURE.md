# 技術設計書

- 文書状態: Draft
- 最終更新日: 2026-10-30

## 1. 採用構成

- 言語: TypeScript
- UI: React
- ビルド: Vite
- スタイル: CSS Modules + CSS Custom Properties
- ホスティング: Vercel
- バージョン管理: GitHub
- テスト候補: Vitest、React Testing Library、Playwright

Next.jsは初版では採用しない。初版は単一の架空PC内で画面状態を切り替えるクライアント中心のアプリであり、サーバーレンダリングや検索エンジン向け最適化を必要としないためである。

## 2. 設計原則

- 画面とロック状態を型で明示する。
- タイマー処理を各画面へ重複実装しない。
- 表示用データとUIコンポーネントを分離する。
- ネットワーク障害が監視カメラ機能を停止させないようにする。
- 入退室ログのデータ元をUIから分離し、後から差し替えられるようにする。
- 外部サービスの障害や認証情報を監視カメラ機能へ波及させない。

## 4. 状態管理

初版はReactのreducerとContextを基本とし、外部状態管理ライブラリは必須にしない。状態遷移が複雑化した場合のみ専用ライブラリを再検討する。

状態は次の領域に分ける。

- 現在の画面
- 監視カメラ入口の解除状態
- 映像1・2の解除集合
- 選択ファイル
- 動画再生状態
- 認証処理中の状態
- 放置警告と経過時間

デスクトップの約0.9秒のアプリ起動演出は、画面遷移前の一時的なUI状態として`DesktopScreen`内に閉じ込める。起動タイマーはコンポーネント破棄時に解除し、アプリ全体の画面状態やロック状態には混在させない。1回クリック用の選択状態は保持しない。

解除状態はメモリ内だけに保持する。`localStorage`などへ保存しない。

## 5. 回答判定

回答判定は純粋関数として実装し、UIから分離する。

### 共通処理

- 文字列前後の空白を削除する。
- 入力が存在しない場合は不正解とする。

### 監視カメラ入口

- ひらがなとカタカナを同一視する。
- 正解語は「メンテナンス」。

### 映像1・2

- 英字の大文字・小文字を同一視する。
- 映像1は`UNIVERSE`。
- 映像2は`TAIATARI`。

実装時にUnicode正規化を行い、全角英字などを許容するかはテスト例を提示して承認を得る。

## 6. 入退室ログのデータ境界

入退室ログUIは、データの取得元へ直接依存させない。

```ts
interface AccessLogRepository {
  list(): Promise<AccessLogEntry[]>;
}
```

採用実装:

- `StaticAccessLogRepository`: リポジトリ内の確定データ4件を読む。

イベント中にデータを更新する要件がないため、データベース、Google Sheets、GASは使用しない。日付、時刻、名前、社員ID、入退室、対象区画を型で固定し、オフラインでも同じ内容を返す。

画面は`AccessLogRepository`だけを参照し、将来データ元を変更する場合も画面全体を書き直さずに済む境界を維持する。

## 7. オフライン方針

- UI、ロゴ、書体、謎画像、監視映像を同一配信元またはローカル資産として扱う。
- 外部CDNや外部フォントを必須にしない。
- Service Workerによってアプリシェルと必要資産をキャッシュする案を基本とする。
- 動画は容量が大きくなる可能性があるため、実ファイル受領後に容量とブラウザ保存上限を検証する。
- 本番前に対象PCでオフライン起動と5本すべての再生を実測する。
- キャッシュだけで確実性が不足する場合は、同じ静的ビルドを対象PC内から配信するローカル予備手段を用意する。
- オフライン対応は「一度オンラインで開けば多分動く」状態をもって完了としない。

### 現在の実装

- Service Workerのインストール時に、`index.html`から本番ビルドのハッシュ付きJavaScript/CSSを検出し、アプリシェルとロゴを同一キャッシュへ保存する。
- 画面遷移はネットワーク優先・キャッシュ代替、同一配信元の静的資産はキャッシュ優先とする。
- Service Workerが制御を開始した端末では、ヘッダーに`LOCAL READY`を表示する。
- 通信断を検知した場合は`OFFLINE LOCAL`を表示する。
- 現在の固定データとUIは、配信サーバーを停止した状態での再読み込みと主要導線を確認済み。
- 最終動画は未受領のため、5本の動画を含むキャッシュ容量と対象PC再起動後の再生確認は最終素材統合時に行う。

## 8. レスポンシブ方針

- デスクトップ優先。
- 特定の解像度へ固定しない。
- 横幅が狭い場合は、左右パネルの幅を縮小または折りたたむ。
- PCホームでは`AppShell`の共通ヘッダーとフッターを隠し、`DesktopScreen`が壁紙、ショートカット、タスクバーを含む全画面デスクトップを所有する。
- PCホームのアプリ起動要素は見た目をショートカットに寄せても、キーボード操作可能なbutton要素を維持する。
- スタートメニュー、検索語、ネットワーク情報、クイック状態、日時パネルの開閉は`DesktopScreen`内の一時的なUI状態として保持し、アプリ全体のreducerへ追加しない。
- クリック可能な外観を持つ要素はbuttonまたはinputとして実装し、装飾だけのbutton要素は作らない。
- 動画の縦横比を維持する。
- 謎入力、再生操作、ホーム操作を常に操作可能な位置へ置く。
- 正確なブレークポイントは、最初の画面モックと対象PC確認後に確定する。

### 全画面表示と認証モーション

- 動画全画面表示はFullscreen APIを使い、プレイヤーと操作列を同じ全画面要素に含める。
- `fullscreenchange`で表示状態を同期し、ブラウザのEsc操作による終了もUIへ反映する。
- 認証の成否判定は既存の純粋関数とreducerに残し、約2.8秒の視覚演出は`AuthPanel`へ閉じ込める。
- 不正解から`idle`へ戻る状態変化を検知して入力値を消去し、同じ画面で再試行できるようにする。
- 認証モーションはCSSで実装し、`prefers-reduced-motion`時は静的な結果表示へ切り替える。
- 入口認証の結果は入力パネル内へ小さい`popupResult`として絶対配置し、入力画面を暗幕越しに残す。映像個別認証は`inlineResult`で入力パネル全体を置き換える。どちらも左へ認証記号、右へ結果文、下へ進行表示を割り当てる。
- 映像1・2の認証待ちは`pendingArchiveId`だけで表し、`CameraSystemScreen`の中央表示を認証専用画面へ差し替えない。`position: fixed`のモーダル暗幕を監視画面全体へ重ね、背景操作を遮断する。認証前の暗幕クリックまたはEscキーでは`pendingArchiveId`だけを解除し、直前の`selectedFileId`と中央表示を維持する。認証判定中は暗幕から閉じない。
- `AuthPanel`の入口認証には`popupResult`、映像1・2には`compact`を指定する。`popupResult`は背景を暗くする影と小型の判定ウィンドウを表示し、`compact`は認証パネル全体の内部で結果へ切り替える。
- `compact`かつ`granted`の場合だけ、SVG錠前のツルを開くCSSアニメーション、`ARCHIVE LOCK RELEASED`、四辺を順に描く外周線、上から下へ通過する走査線を表示する。中央分割用の疑似要素と入口用`handoffBloom`は個別認証では無効化し、追加の認証状態を増やさず既存の約2.8秒の`granted`状態内で完結させる。
- 不正解結果には終了前の`opacity`・`clip-path`消去アニメーションを設定しない。reducerが約2.8秒後に`idle`へ戻すまで結果を保持し、同じReact更新で結果を外して入力状態を見せる。

### 仮監視映像素材

- 仮静止画は`public/assets/surveillance/placeholders/`にローカル資産として保持し、外部Driveへの実行時接続に依存しない。
- アーカイブごとの素材パスと代替テキストは`src/data/surveillance-files.ts`に集約する。
- 実動画受領後は、画面遷移やロック状態を変更せず、このメディア定義と`VideoPlayer`の再生ソースを交換する。
- 5枚の仮静止画はService Workerのアプリシェルに含め、初回準備後のオフライン表示を保持する。

### 常時モーションと画面遷移

- `DynamicBackdrop`をアプリの画面分岐より上位へ一度だけ配置し、画面遷移でCanvasを再生成しない。
- 共通背景は依存ライブラリを追加しないWebGLシェーダーで描画する。画面種別の変更時はuniform値を補間し、背景の色、波形、光面を連続的に変化させる。
- 描画解像度は端末のdevice pixel ratioを最大1.25に制限し、常時背景は30fpsを上限とする。Canvas寸法は毎フレーム確認せず、初期化時とリサイズ時だけ更新する。タブ非表示時は描画を停止する。
- WebGL初期化に失敗した場合は同系統のCSS背景へフォールバックする。WebGLを必須機能にしない。
- 前面UIの常時モーションはCSSの`transform`と`opacity`を中心にし、走査・波形・回転・奥行き変形を共通の視覚言語として使う。画面ごとの役割が異なるため、同じ方向のワイプを全画面へ機械的に再利用しない。
- `App`の画面分岐を画面状態でkey付けした`screenStage`で包み、背景Canvasを保持したまま`data-transition`でデスクトップ、認証、監視、入退室ログの転換方式を切り替える。転換のラベルは画面の役割を表す語とし、意味のない章番号は状態として保持しない。個別画面はCSSカスタムプロパティで行番号を受け取り、一覧や端末出力を段階表示する。
- 認証入力と約2.8秒の判定演出は`AuthPanel`内の同じコンソール構造へ閉じ込める。入力フォーカスによる視覚変化はCSSで行い、認証状態や回答判定へ新しい状態を追加しない。現在の入口・映像個別認証はどちらもPortalを使用しない。
- 認証中の色はCSSアニメーションの前半を中立色に固定し、約1.1秒後の判定表示で初めて成功色または失敗色へ変える。入口認証成功後の監視アーカイブ転換は認証ウィンドウの結果表示を終えてから開始し、巨大な結果面や切り抜きグラデーションを再導入しない。
- `authorized`転換の左右シャッターはそれぞれ画面幅の50%を占める。汎用の左疑似要素に設定された円形`mask-image`は`none`へ上書きし、左右を同じ不透明度で描画する。
- 機能アイコンは外部画像やアイコン配信へ依存せず、リポジトリ内のSVGまたはCSS図形で構成する。色と線幅は共通トークンに従い、装飾用アイコンにも操作可能と誤認させるボタン表現を使わない。
- 監視映像一覧は同じアイコン枠の内部を状態別インラインSVGへ切り替え、ロック中は閉じた弦・本体・鍵穴を持つ錠前、閲覧可能は再生三角を表示する。選択状態は四辺が同じ強さの境界線と単色面で表す。
- すべての連続モーションは`prefers-reduced-motion`で停止または単一フレーム化し、情報と操作結果は静止状態でも理解できるようにする。
- `CinematicOverlay`は画面分岐の外側へ一度だけ配置し、軌道、走査ビーム、左右テレメトリ、下端データ帯を描画する。カーソル追従要素と`pointermove`監視は持たない。
- `CinematicOverlay`は`pointer-events: none`とし、狭幅では左右テレメトリを省略する。`prefers-reduced-motion`では連続アニメーションを停止する。
- 入退室ログは`AccessLogRepository`の4件を変更せず、左側の記録コンテキストと右側の時系列トレースへ表示する。狭幅では概要を上段、時系列を下段へ積み替える。
- 監視映像未選択時の待機領域は、固定データからカメラノード、録画時刻範囲、ファイル数、暗号化数を表示し、軽量なCSS波形だけを連続描画する。新しい状態や外部取得は追加しない。
- 待機領域の会社規模は、固定のカメラファブリック24ノードと現在のローカルバッファ5件で表す。別映像をデータとして追加せず、ノード図と診断値は操作不能な状態表示として描画する。
- 24ノード状態図は`CameraSystemScreen`内の静的SVGとCSS Modulesで描画し、外部画像、Canvasライブラリ、追加データ取得へ依存しない。接続線と点の動きは`transform`、`opacity`、`stroke-dashoffset`に限定し、`prefers-reduced-motion`では停止する。
- Illustratorの正式ロゴ原稿は`design/source/`へ保管し、実行時は`public/assets/brand/`の透過PNGだけを読む。透過PNGはService Workerの事前キャッシュへ含める。

### システム効果音

- `useUiSounds`を効果音の単一境界とし、画面コンポーネントごとにAudioContextを生成しない。
- 最初の`pointerdown`または`keydown`でAudioContextを生成・再開する。
- 効果音は短いオシレーターの組み合わせで生成し、音声素材、外部CDN、通信を必要としない。
- reducerの状態は音声の成否へ依存させない。画面、認証、動画状態の変化を監視して副作用として再生する。
- 動画メディアの音声トラックおよび音量操作は追加しない。

## 9. テスト方針

### 単体テスト

- 回答の正規化と正誤判定
- 画面遷移reducer
- ホーム復帰時の全ロックリセット
- 10秒警告、20秒復帰
- 動画再生中のタイマー停止

### コンポーネントテスト

- デスクトップショートカットの1回クリック非遷移、ダブルクリック起動、起動中表示
- 認証成功・失敗表示
- ホーム確認の戻る／キャンセル
- ロックされた映像と閲覧可能映像の表示差
- ロック映像の認証モーダル背後に監視画面が維持されること
- 個別認証は暗幕クリックで閉じ、送信後の結果は同じモーダル内に留まること
- システムファイルが動画として扱われないこと

### ブラウザテスト

- ホームから監視カメラを開き、入口ロックを解除する
- 映像1・2をそれぞれ解除する
- ホームへ戻り、再入場時に全ロックされている
- 入退室ログを直接開ける
- 放置警告と自動ホーム復帰
- 動画再生中に自動復帰しない
- 代表的なPC画面幅で操作できる
- ネットワークを切った状態で主要機能と動画が使える

## 10. セキュリティ上の位置づけ

初版の認証は謎解き演出である。静的フロントエンドとオフライン動作を優先するため、技術に詳しい利用者が配信ファイルを調べれば答えや動画へ到達できる可能性がある。実際のアクセス制御が必要になった場合は別要件として設計し直す。
